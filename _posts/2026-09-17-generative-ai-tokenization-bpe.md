> **이번 글의 목표:** 단어·문자·서브워드 토큰화의 차이를 구분하고, 작은 한국어 말뭉치에서 BPE가 빈번한 글자 쌍을 합쳐 토큰과 정수 ID를 만드는 과정을 직접 계산한다.

먼저 결과부터 보자. `토큰화 토큰 문장`을 아주 작은 말뭉치에서 두 번 병합하면 `['토큰화', '토큰', '문', '장']`이 된다. 이 토큰에 어휘표의 정수 ID를 붙이면 `[3, 2, 0, 1]`이다. 문장이 곧바로 하나의 숫자가 된 것이 아니라, **조각으로 나뉜 뒤 각 조각이 번호로 바뀐 것**이다.

이 글은 생성형 AI 시리즈의 첫 단원이다. 전체 학습 지도의 위치가 궁금하다면 먼저 [블로그의 기반 지식과 지능형 시스템 영역을 소개한 글]({{ '/posts/welcome/' | relative_url }})을 보면 좋다.

## 1. 직관: 모델은 문장을 어떤 조각으로 볼까?

사람은 `토큰화`를 하나의 단어로 읽는다. 모델에 넣기 전에는 이 문자열을 미리 정한 단위로 나누고 각 단위에 정수 ID를 붙여야 한다. 이때 나눈 단위가 **토큰(token)**, 나누는 과정이 **토큰화(tokenization)**다. 토큰은 반드시 완전한 단어가 아니다.

- 단어 단위는 뜻을 담기 쉽지만, 모든 단어와 활용형을 어휘표에 넣으면 표가 커지고 처음 보는 단어를 처리하기 어렵다.
- 문자 단위는 새로운 단어도 표현할 수 있지만, 한 문장이 너무 긴 토큰 열이 되기 쉽다.
- 서브워드 단위는 자주 나오는 덩어리는 크게 유지하고 드문 표현은 더 작은 조각으로 나눈다.

그래서 많은 언어 모델은 단어와 문자 사이에 있는 **서브워드 토큰화**를 사용한다. 다만 같은 문장도 토크나이저의 학습 자료, 어휘표, 병합 규칙이 다르면 토큰 경계와 개수가 달라진다. 띄어쓰기 수나 글자 수만 보고 실제 토큰 수를 단정할 수 없는 이유다.

## 2. 기호와 수식: 문자열에서 ID 열까지

문자열을 $x$, 토크나이저를 $T$, 어휘표를 $V$라고 하자. 토큰화 결과는 다음처럼 쓸 수 있다.

$$
T(x)=(t_1,t_2,\ldots,t_n), \qquad V(t_i)=z_i
$$

$t_i$는 $i$번째 토큰이고, $z_i$는 그 토큰에 대응하는 정수 ID다. 최종 입력은 $(z_1,z_2,\ldots,z_n)$이라는 정수열이다. ID의 크기에는 순서나 의미가 없다. ID 3이 ID 2보다 더 크거나 중요하다는 뜻이 아니라, 어휘표에서 서로 다른 행을 찾기 위한 주소에 가깝다.

BPE(Byte Pair Encoding)는 서브워드 어휘를 만드는 한 방법이다. 학습 말뭉치를 작은 단위로 시작한 뒤, 서로 붙어 가장 자주 나타나는 쌍을 하나의 새 토큰으로 합친다. 한 단계의 병합 규칙을 단순화하면 다음과 같다.

$$
(a^*,b^*)=\arg\max_{(a,b)} c(a,b)
$$

$c(a,b)$는 인접한 토큰 쌍 $(a,b)$이 말뭉치에 나온 횟수다. 가장 빈번한 쌍을 합친 뒤 빈도를 다시 세고, 목표한 어휘 크기나 병합 횟수에 도달할 때까지 반복한다.

## 3. 작은 손계산: `토`와 `큰`을 먼저 합치기

예제 말뭉치에서 `토큰화`는 2번, `토큰`은 1번, `문장`은 1번 등장한다고 하자. 처음에는 각 글자를 하나의 토큰으로 둔다.

| 단어 | 빈도 | 처음 분할 |
| --- | ---: | --- |
| 토큰화 | 2 | 토 · 큰 · 화 |
| 토큰 | 1 | 토 · 큰 |
| 문장 | 1 | 문 · 장 |

인접 쌍 `토+큰`은 총 3번으로 가장 자주 나온다. 첫 병합 뒤에는 `토큰 · 화`, `토큰`, `문 · 장`이 된다. 이제 `토큰+화`가 2번으로 가장 많으므로 두 번째 병합에서 `토큰화`가 새 토큰이 된다.

두 규칙을 `토큰화 토큰 문장`에 순서대로 적용하면 `토큰화`, `토큰`, `문`, `장` 네 토큰이 남는다. 정렬한 어휘표를 `문:0`, `장:1`, `토큰:2`, `토큰화:3`으로 정하면 ID 열은 `[3, 2, 0, 1]`이다. 실제 토크나이저는 훨씬 큰 자료와 어휘를 사용하며, 바이트 수준 처리나 특수 토큰 같은 규칙도 더한다. 여기서는 빈도 기반 병합만 분리해 본다.

## 4. 실행 가능한 Python 실습

다음 코드는 외부 패키지 없이 같은 두 번의 병합을 학습하고 새 문장을 인코딩한다. 빈도가 같을 때는 글자 순으로 앞선 쌍을 고르게 해 실행 결과를 결정적으로 만들었다.

```python
from collections import Counter

word_freq = {"토큰화": 2, "토큰": 1, "문장": 1}
sequences = {word: list(word) for word in word_freq}
rules = []

for step in range(2):
    pair_counts = Counter()
    for word, tokens in sequences.items():
        for pair in zip(tokens, tokens[1:]):
            pair_counts[pair] += word_freq[word]

    best = min(pair_counts, key=lambda p: (-pair_counts[p], p))
    merged = "".join(best)
    rules.append(best)

    for word, tokens in sequences.items():
        new_tokens = []
        i = 0
        while i < len(tokens):
            if i + 1 < len(tokens) and (tokens[i], tokens[i + 1]) == best:
                new_tokens.append(merged)
                i += 2
            else:
                new_tokens.append(tokens[i])
                i += 1
        sequences[word] = new_tokens

    print(f"병합 {step + 1}: {best[0]} + {best[1]} -> {merged} ({pair_counts[best]}회)")


def tokenize(text):
    result = []
    for word in text.split():
        tokens = list(word)
        for left, right in rules:
            merged_tokens = []
            i = 0
            while i < len(tokens):
                if i + 1 < len(tokens) and (tokens[i], tokens[i + 1]) == (left, right):
                    merged_tokens.append(left + right)
                    i += 2
                else:
                    merged_tokens.append(tokens[i])
                    i += 1
            tokens = merged_tokens
        result.extend(tokens)
    return result


tokens = tokenize("토큰화 토큰 문장")
vocab = {token: i for i, token in enumerate(sorted(set(tokens)))}
ids = [vocab[token] for token in tokens]

print("토큰:", tokens)
print("어휘표:", vocab)
print("ID:", ids)
```

실행 출력은 다음과 같다.

```text
병합 1: 토 + 큰 -> 토큰 (3회)
병합 2: 토큰 + 화 -> 토큰화 (2회)
토큰: ['토큰화', '토큰', '문', '장']
어휘표: {'문': 0, '장': 1, '토큰': 2, '토큰화': 3}
ID: [3, 2, 0, 1]
```

## 5. 결과 해석: ID는 의미가 아니라 찾아갈 위치다

출력의 첫 두 줄은 손계산과 같다. 많이 반복된 `토+큰`이 먼저 합쳐지고, 그 결과 생긴 `토큰`과 `화`가 다음에 합쳐졌다. 학습한 규칙에는 순서가 있으므로 새 문자열에도 첫 규칙부터 차례로 적용한다.

여기서 `[3, 2, 0, 1]` 자체는 아직 의미 벡터가 아니다. 각 숫자는 어휘표의 항목을 가리킨다. 다음 단계에서 모델은 이 ID를 사용해 학습 가능한 벡터를 찾는다. [퍼셉트론과 가중합을 계산한 글]({{ '/posts/deep-learning-perceptron-relu/' | relative_url }})을 함께 보면, 토큰이 숫자 벡터가 된 뒤 신경망의 가중 계산으로 이어진다는 큰 흐름을 잡는 데 도움이 된다.

또한 이 실습은 공백을 단어 경계로 사용하고 공백 자체는 버린다. 실제 토크나이저는 공백을 토큰에 포함하기도 하고, 유니코드 문자를 바이트로 바꾼 뒤 BPE를 적용하기도 한다. 그러므로 이 코드의 토큰 수를 특정 상용 모델의 입력 길이나 비용 계산에 그대로 사용하면 안 된다. 사용할 모델에 연결된 공식 토크나이저로 다시 재야 한다.

토큰화는 맞춤법 교정이나 불필요한 문자를 지우는 텍스트 정제와도 다르다. 토크나이저는 입력을 모델의 어휘표와 연결하는 규칙이므로, 임의로 띄어쓰기나 유니코드 표현을 바꾸면 토큰 열도 달라질 수 있다. 겉으로 같은 글자처럼 보여도 내부 코드가 다르면 서로 다른 바이트 열에서 출발할 수 있기 때문이다. 반대로 BPE 기반 토크나이저는 학습 때 보지 못한 표현도 작은 단위로 나누어 나타낼 수 있다. 이것은 모르는 단어를 곧바로 버리지 않는다는 장점이지만, 잘게 쪼개진 표현이 자동으로 잘 이해된다는 보장은 아니다.

토큰 수는 모델이 한 번에 받을 수 있는 입력 길이를 셀 때도 쓰인다. 같은 뜻을 더 짧게 썼다고 해서 언제나 토큰 수도 같은 비율로 줄어드는 것은 아니다. 언어, 숫자, 기호, 공백의 조합에 따라 분할 결과가 달라지기 때문이다. 따라서 입력 길이를 확인할 때는 글자 수 추정치보다 실제 토크나이저의 인코딩 결과를 기준으로 삼아야 한다.

## 6. 직접 바꿔 보는 연습

먼저 `range(2)`를 `range(1)`로 바꿔 보자. 두 번째 병합이 사라져 `토큰화`는 `토큰`, `화`로 나뉘고 전체 토큰 수는 5개가 된다. 병합을 더 많이 학습하면 자주 본 문자열은 더 큰 토큰으로 남을 수 있다는 점을 확인할 수 있다.

다음으로 말뭉치에 `"문장": 4`를 넣어 보자. 첫 단계에서 `문+장`의 빈도가 4가 되어 `토+큰`의 3보다 커진다. 학습 자료의 빈도가 병합 순서와 최종 어휘를 바꾼다는 뜻이다. 마지막으로 입력을 `토큰화 새문장`으로 바꾸고, 학습 때 자주 보지 못한 문자열이 더 작은 글자 조각으로 남는지 확인해 보자.

## 핵심 요약

- 토큰화는 문자열을 토큰으로 나누고, 각 토큰을 어휘표의 정수 ID로 바꾸는 과정이다.
- 서브워드 토큰화는 자주 본 덩어리는 크게, 드문 표현은 더 작은 조각으로 나타내 단어와 문자 단위의 절충점을 만든다.
- BPE는 인접 쌍의 빈도를 세어 가장 자주 나온 쌍부터 반복해서 합친다.
- 토큰 경계와 개수는 토크나이저마다 다르므로 실제 모델의 공식 토크나이저로 확인해야 한다.
