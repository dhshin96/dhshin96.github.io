> **이번 글의 목표:** 토큰 ID가 임베딩 표의 한 행을 고르는 과정을 이해하고, 두 벡터의 코사인 유사도를 손계산과 Python으로 확인한다.

먼저 결과부터 보자. 앞 글에서 만든 ID 열 `[3, 2, 0, 1]`을 작은 임베딩 표에 넣으면 `[[0.8, 0.6], [1.0, 0.0], [0.0, 1.0], [-0.8, 0.6]]`이 나온다. ID 3은 숫자 3의 크기를 계산에 쓰는 대신 **표의 3번 행**을 고른다. 그 행의 두 실수 `[0.8, 0.6]`이 신경망이 처리할 입력이다.

아직 토큰과 ID의 관계가 낯설다면 [BPE로 `[3, 2, 0, 1]`을 만든 토큰화 글]({{ '/posts/generative-ai-tokenization-bpe/' | relative_url }})부터 읽는 편이 좋다. 이번 글은 그 숫자열이 만들어진 바로 다음 단계에서 시작한다.

## 1. 직관: ID는 주소, 임베딩은 그 주소의 내용

ID는 토큰을 구별하는 정수 주소다. ID 3이 ID 2보다 뜻이 더 크다는 의미는 없다. 주소만 신경망에 넣으면 토큰 사이의 관계를 계산하기 어렵기 때문에, 모델은 각 주소에 같은 길이의 실수 벡터를 연결한다. 이 대응표가 **임베딩 행렬**이다.

어휘가 4개이고 벡터 차원이 2라면 임베딩 행렬에는 4개의 행과 2개의 열이 있다. 입력 ID가 3이면 네 번째 행 `[0.8, 0.6]`을 꺼낸다. 같은 ID는 같은 행을 고르므로 같은 벡터에서 출발한다. 실제 언어 모델의 차원과 어휘 크기는 훨씬 크지만, 행 조회라는 핵심은 같다.

여기서 표의 값은 원리를 보이기 위해 직접 정한 숫자다. 실제 모델에서는 임베딩 행렬도 가중치이므로 학습 과정에서 손실을 줄이는 방향으로 갱신된다. 비슷한 문맥에서 비슷한 역할을 하는 토큰이 가까운 표현을 얻을 수 있지만, 각 좌표를 사람이 미리 `문법`, `주제`처럼 이름 붙여 입력하는 것은 아니다.

## 2. 기호와 수식: 행 조회와 방향 비교

어휘 크기를 $|V|$, 임베딩 차원을 $d$라고 하면 임베딩 행렬은 $E\in\mathbb{R}^{|V|\times d}$다. 토큰 ID가 $i$일 때 조회 결과는 다음처럼 한 행을 고른다.

$$
\mathbf{e}_i=E[i]\in\mathbb{R}^{d}
$$

ID 열의 길이가 $n$이면 출력 모양은 $n\times d$가 된다. 예제에서는 입력 4개와 차원 2이므로 출력은 $4\times2$다. 이 모양을 먼저 확인하면 토큰 수와 벡터 차원을 뒤섞지 않을 수 있다.

두 벡터 $\mathbf{x}$와 $\mathbf{y}$의 방향이 얼마나 비슷한지는 코사인 유사도로 비교할 수 있다.

$$
\operatorname{cos}(\mathbf{x},\mathbf{y})=
\frac{\mathbf{x}\cdot\mathbf{y}}{\|\mathbf{x}\|_2\|\mathbf{y}\|_2}
$$

0이 아닌 벡터끼리 계산하면 값은 $-1$에서 $1$ 사이다. 1에 가까우면 같은 방향, 0이면 직교, -1에 가까우면 반대 방향이다. 다만 높은 코사인 유사도가 언제나 사람이 느끼는 동의어 관계를 보장하는 것은 아니다. 벡터가 어떤 자료와 학습 목표로 만들어졌는지가 해석의 범위를 정한다.

## 3. 작은 손계산: `토큰화`와 `토큰`은 0.8

설명용 표에서 `토큰화`의 벡터를 $\mathbf{x}=(0.8,0.6)$, `토큰`의 벡터를 $\mathbf{y}=(1.0,0.0)$으로 두자. 내적은 $0.8\times1.0+0.6\times0.0=0.8$이다. 두 벡터의 길이는 각각 다음과 같다.

$$
\|\mathbf{x}\|_2=\sqrt{0.8^2+0.6^2}=1,
\qquad \|\mathbf{y}\|_2=\sqrt{1^2+0^2}=1
$$

따라서 코사인 유사도는 $0.8/(1\times1)=0.8$이다. `문`의 벡터 $(0,1)$과 `토큰`은 내적이 0이므로 유사도도 0이다. 이 숫자는 손계산을 쉽게 하려고 만든 결과이지, 한국어 토큰의 실제 의미 유사도를 측정한 값은 아니다.

## 4. 실행 가능한 Python 실습

다음 코드는 외부 패키지 없이 행 조회, 출력 모양, 코사인 유사도를 재현한다. 0벡터는 방향이 없으므로 분모가 0이면 오류를 내도록 했다.

```python
from math import sqrt

tokens = ["문", "장", "토큰", "토큰화"]
embedding_table = [
    [0.0, 1.0],
    [-0.8, 0.6],
    [1.0, 0.0],
    [0.8, 0.6],
]
ids = [3, 2, 0, 1]


def cosine_similarity(x, y):
    dot = sum(a * b for a, b in zip(x, y))
    norm_x = sqrt(sum(a * a for a in x))
    norm_y = sqrt(sum(b * b for b in y))
    if norm_x == 0 or norm_y == 0:
        raise ValueError("0벡터의 방향은 비교할 수 없습니다.")
    return dot / (norm_x * norm_y)


vectors = [embedding_table[token_id] for token_id in ids]
print("벡터:", vectors)
print("출력 모양:", (len(vectors), len(vectors[0])))

query_id = 2  # 토큰
for token_id, token in enumerate(tokens):
    if token_id != query_id:
        score = cosine_similarity(
            embedding_table[query_id], embedding_table[token_id]
        )
        print(f"토큰 ↔ {token}: {score:.1f}")
```

실행 출력은 다음과 같다.

```text
벡터: [[0.8, 0.6], [1.0, 0.0], [0.0, 1.0], [-0.8, 0.6]]
출력 모양: (4, 2)
토큰 ↔ 문: 0.0
토큰 ↔ 장: -0.8
토큰 ↔ 토큰화: 0.8
```

## 5. 결과 해석: 조회와 학습을 분리해서 보기

첫 출력은 ID 순서대로 행을 고른 결과다. `[3, 2, 0, 1]`의 첫 ID 3이 네 번째 행을, 다음 ID 2가 세 번째 행을 선택했다. 출력 모양 `(4, 2)`에서 4는 토큰 개수이고 2는 토큰 하나를 나타내는 좌표 수다.

유사도는 `토큰화` 0.8, `문` 0.0, `장` -0.8 순이다. 이것은 우리가 그렇게 보이도록 표를 설계했기 때문이다. 코드가 의미를 발견하거나 임베딩을 학습한 것은 아니다. 실제 학습에서는 예측 오차를 줄이도록 표의 값이 반복해서 바뀐다. [가중치와 가중합의 기초를 계산한 퍼셉트론 글]({{ '/posts/deep-learning-perceptron-relu/' | relative_url }})을 보면 임베딩 행렬도 학습 가능한 가중치라는 말을 이해하는 데 도움이 된다.

또 하나의 주의점은 **토큰 임베딩만으로 문맥이 완성되지 않는다**는 것이다. 같은 토큰 ID는 조회 직후 같은 벡터를 얻지만, Transformer 안에서는 위치 정보와 주변 토큰의 영향을 받아 각 자리의 표현이 달라진다. 따라서 이 글의 2차원 표를 문장 전체의 의미 벡터나 최종 모델 출력으로 확대 해석하면 안 된다. 이번 단계는 Transformer가 처리할 초기 벡터를 만드는 입구다.

## 6. 직접 바꿔 보는 연습

먼저 `ids`를 `[2, 3, 2]`로 바꾸자. 출력 모양은 `(3, 2)`가 되고, 같은 ID 2가 두 번 같은 벡터 `[1.0, 0.0]`을 고르는지 확인할 수 있다.

다음으로 `토큰화` 벡터를 `[0.6, 0.8]`로 바꿔 보자. 길이는 여전히 1이지만 `토큰`과의 코사인 유사도는 0.6으로 줄어든다. 벡터의 길이보다 방향이 달라졌기 때문이다. 마지막으로 한 행을 `[0.0, 0.0]`으로 바꾸어 오류가 나는 이유를 수식의 분모와 연결해 설명해 보자.

## 핵심 요약

- 토큰 ID는 수치적 크기를 쓰는 값이 아니라 임베딩 행렬의 행 주소다.
- 임베딩 조회 결과의 모양은 `토큰 수 × 임베딩 차원`이다.
- 코사인 유사도는 두 벡터의 방향을 비교하지만, 그 값의 의미는 벡터를 만든 자료와 학습 목표에 달려 있다.
- 실제 토큰 임베딩은 학습 가능한 가중치이며, Transformer 안에서 문맥을 반영한 표현으로 계속 변한다.
